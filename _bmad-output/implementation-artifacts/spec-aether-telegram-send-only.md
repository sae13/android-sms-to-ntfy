## Intent

**Problem:** دریافت دائمی پاسخ از اعلانها و تلگرام، مصرف باتری و پیچیدگی سرویس را بالا میبرد. ارسال تلگرام در شبکهٔ محدود نیز باید بدون نصب ترموکس یا یک برنامهٔ جدا، از مسیر سالم عبور کند.

**Approach:** همهٔ مسیرهای پاسخ پیامکی حذف میشوند و تلگرام به مقصد فقط-ارسال تبدیل میشود. هستهٔ اصلی ایثر، با اقتباس حداقلی از روش اجرای اندرویدی پروژهٔ مرجع، داخل برنامه بستهبندی میشود؛ برنامه مسیرهای هسته را با عبور واقعی داده میآزماید و تلگرام را از پراکسی محلی سالم میفرستد.

## Boundaries & Constraints

**Always:** مسیرهای ارسال پیامک، تماس، انتیفای، دلتاچت و تلگرام مستقل میمانند؛ شکست یا توقف ایثر نباید سرویس یا مقصدهای دیگر را متوقف کند. حالت پیشفرض پراکسی «فقط هنگام ارسال تلگرام» است و پس از پایان کار خاموش میشود؛ گزینهٔ جداگانه آن را تا زمان اجرای سرویس روشن نگه میدارد. گزینهٔ مستقل «پراکسی همگانی» هر دو پراکسی SOCKS5 و HTTP CONNECT را بهترتیب روی پورتهای 1819 و 1820 و نشانی 0.0.0.0 در دسترس شبکه قرار میدهد؛ در حالت عادی هر دو فقط روی 127.0.0.1 گوش میدهند. رابط کاربری پیش از فعالسازی پراکسی همگانی، خطر پراکسی باز بدون احراز هویت را واضح نشان میدهد. انتخاب مسیر باید با بررسی واقعی داده انجام شود و آخرین مسیر سالم برای اتصال سریع بعدی استفاده شود. هسته از نسخهٔ ثابت منبع ساخته میشود، برای معماری دستگاه بستهبندی میشود و اعلانهای مجوز و منبع متناظر همراه انتشار میماند. اسرار و نشانیهای حساس در لاگ یا مخزن ثبت نمیشوند.

**Never:** رابط کاربری، ویپیان سراسری، تونل تبدیل ترافیک، سایفون، کلواک، موتور اچایوی، فهرست سرور و دیگر اجزای پروژهٔ مرجع وارد نمیشوند. پاسخ تلگرام، دریافت دورهای تلگرام، دریافت پاسخ انتیفای، ارسال پیامک از راه دور و جدولهای آنها باقی نمیمانند. استفاده از یک آزمون صرفاً سوکتی بهجای عبور واقعی درخواست تلگرام پذیرفته نیست. تغییرات ثبت یا به مخزن راه دور ارسال نمیشوند مگر با دستور صریح کاربر.

## Tasks & Acceptance Criteria

### Task 1: حذف قابلیتهای پاسخ
- حذف SSE، polling تلگرام، ارسال SMS از راه دور، تنظیمات، اعلانها، DAOها و آزمونهای مختص آنها؛ ایجاد مهاجرت Room بعدی.
- **Given** نصب ارتقایافته یا تازه **When** برنامه اجرا میشود **Then** ارسال مقصدها و لاگها سالمند و هیچ اتصال دریافت پاسخ یا مجوز ارسال پیامک لازم نیست.

### Task 2: افزودن لایهٔ حداقلی ایثر
- باینری معماری مناسب، مدیر فرایند همزمانی-امن، پروفایل کممصرف، مهلت شروع/توقف و بررسی واقعی Telegram Bot API را پیاده کن.
- **Given** حداقل یک مسیر سالم **When** نشست درخواست میشود **Then** پراکسی محلی آماده و فقط پس از عبور واقعی داده موفق اعلام میشود.

### Task 3: اتصال حالتهای موقت و همیشگی
- ارسال تلگرام را به نشست ایثر وصل و تنظیمات فعالسازی/همیشگی و وضعیت آزمون را اضافه کن.
- **Given** حالت موقت یا همیشگی **When** ارسالها انجام میشوند **Then** عمر فرایند دقیقاً مطابق انتخاب کاربر است و مقصدهای دیگر مستقل میمانند.

### Task 4: ساخت و انتشار تکرارپذیر
- گردشکار را برای ساخت هسته از commit ثابت، کش، ABIهای مجزا، مجوزها و APKهای معماریمحور بهروز کن.
- **Given** اجرای محلی و GitHub Actions **When** آزمون و ساخت اجرا میشوند **Then** واحدها، مهاجرت، debug/release و حضور باینری/اعلان مجوز را اثبات میکنند.
